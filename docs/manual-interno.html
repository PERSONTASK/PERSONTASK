Publicar uma nova versão (deploy)

O deploy é manual (arrastar a pasta). Sempre que o código mudar, gere a build e envie ao Netlify.

1. Gerar a build

Abra o terminal (Git Bash) na pasta do app e rode:

export PATH="/c/Program Files/nodejs:$PATH"   # deixa o Node acessível
cd /c/Users/User/persontask-app
npm run build                                 # gera a pasta dist/

Isso cria/atualiza a pasta persontask-app/dist.

2. Enviar ao Netlify

  1. Acesse o Netlify → site persontask → aba Deploys.
  2. Arraste a pasta dist inteira para a área de drag & drop.
  3. Espere aparecer Published.
  4. No site, dê Ctrl+F5 (o PWA atualiza sozinho no próximo acesso).
✔️

Para conferir se a versão nova subiu sem depender de cache: o nome do arquivo JS muda a cada build (ex.: assets/index-XXXX.js). Se o arquivo no ar tem hash novo, publicou.

💡

O manual do usuário (manual.html) e o PDF ficam em persontask-app/public e vão junto na build. Este manual interno fica em docs/ e não é publicado.

Planos: Grátis e Premium

Ainda não há cobrança automática. O plano de cada usuário fica no campo plan da tabela profiles (valores: free ou premium).

Dar Premium a um cliente (manual)

  1. Supabase → Table Editor → tabela profiles.
  2. Ache a linha do usuário (pela coluna email).
  3. Mude plan de free para premium e salve.
  4. O usuário vê os recursos Premium liberados no próximo carregamento.
RecursoGrátisPremium
Espaços1Vários
Painéis por Espaço1Vários
Imagem de fundo, fonte, cor de coluna, logo—Sim

💳

Quando quiser cobrança automática (Stripe/gateway), dá para plugar depois — o campo plan já é o "interruptor" que o app lê.

E-mails

Há dois caminhos de e-mail, os dois pelo Resend, do domínio verificado:

TipoComo saiQuais
Avisos do appEdge Functions → Resend APIItem atribuído, vencimento (cron), menção, convite
E-mails de contaSupabase Auth → Resend SMTPReset de senha, confirmação, magic link, troca de e-mail

Configurações-chave

  • Remetente: no-reply@persontask.com.br.
  • SMTP (Supabase → Authentication → Emails → SMTP): host smtp.resend.com, porta 465, usuário resend (minúsculo!), senha = Resend API key.
  • Secrets das Functions (Supabase → Edge Functions → Secrets): RESEND_API_KEY, EMAIL_FROM, APP_URL=https://persontask.com.br.
  • Templates PT: em supabase/email-templates/ — colar em Authentication → Emails → Templates.

Ver se um e-mail saiu

Abra Resend → Emails: cada envio aparece com status (Delivered / Bounced). Se não aparece nada, o e-mail não chegou ao Resend (config de SMTP ou a ação não disparou).

📬

Domínio novo pode cair no spam no começo. Está tudo autenticado (SPF/DKIM/DMARC PASS) — é só reputação. Marcar "não é spam" acelera o aquecimento.

Autenticação (login)

  • E-mail/senha e Google (OAuth) — ambos ativos.
  • Google: credenciais no Google Cloud Console. Redirect autorizado: https://wogilvheyciprqqkprol.supabase.co/auth/v1/callback. No Supabase: Authentication → Providers → Google (Client ID + Secret).
  • URLs (Supabase → Authentication → URL Configuration): Site URL https://persontask.com.br; Redirect https://persontask.com.br/**.
  • Recuperar senha: rotas /forgot-password e /reset-password no app; e-mail via Resend SMTP.
🔑

Se um usuário não consegue entrar: Supabase → Authentication → Users permite reenviar recuperação, confirmar e-mail manualmente ou remover o usuário.

8

Banco de dados & segurança

  • Postgres no Supabase com RLS (Row Level Security) por Espaço — cada pessoa só enxerga os Espaços de que participa.
  • Fonte da verdade do schema: supabase/schema.sql (idempotente). Para recriar/reparar: Supabase → SQL Editor → cole e rode.
  • Se uma criação de Espaço falhar com erro 42501, rode o schema.sql de novo (recria as policies).
  • Arquivos (anexos, avatares, fundos): Supabase Storage (buckets attachments, avatars, space-backgrounds).
💾

Backups: confira em Supabase → Database → Backups. No plano gratuito os backups são limitados — se o negócio crescer, o plano Pro traz backups diários e retenção maior.

9

Edge Functions & Cron

As funções de e-mail rodam no Supabase (Deno). São 4:

  • notify-item-assigned — avisa quem virou responsável.
  • notify-mention — avisa quem foi mencionado (@).
  • notify-due-soon — avisa prazos próximos (roda por cron).
  • send-invite — envia o convite para o Espaço.

Reimplantar (se editar uma função)

cd /c/Users/User/persontask-app
npx supabase functions deploy notify-item-assigned notify-mention notify-due-soon send-invite \
  --project-ref wogilvheyciprqqkprol --no-verify-jwt

O cron do vencimento está em supabase/cron.sql (pg_cron + pg_net, ~11:00 UTC). Os secrets das funções ficam em Supabase → Edge Functions → Secrets.

🖥️

O login do Supabase CLI fica guardado no Windows — por isso o deploy das funções roda no seu terminal.

Solução de problemas

SintomaCausa provável / correção
E-mail do Supabase não chega e nada aparece no ResendSMTP: o Username tem que ser resend (minúsculo). Confira também a API key e a porta (465→587).
E-mail cai no spamReputação de domínio novo. Autenticação está OK — marque "não é spam"; melhora com o uso.
Criar Espaço dá erro 42501Rode supabase/schema.sql de novo (recria as policies de RLS).
"Instalar app" não apareceÍcones PWA precisam existir em public/icons (192/512 PNG) — rebuild + deploy.
Rota abre página em branco / 404 no NetlifySPA: garantir public/_redirects (/* /index.html 200).
Login Google dá "provider not enabled"Ativar Google em Supabase → Providers e conferir o redirect no Google Cloud.
Fonte não muda (Premium)A família precisa estar carregada no index.html (Google Fonts).
