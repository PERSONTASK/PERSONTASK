Cinco serviços sustentam o PERSONTASK. Se um cair, você precisa saber qual.

O domínio ainda está no Netlify. O app novo roda em persontask.joabe-reis2.workers.dev. O persontask.com.br continua apontando para o Netlify até a troca de DNS — veja a seção 7.

Publicar uma nova versão

Não existe mais arrastar pasta. O fluxo é um só:

  1. Testar localmente: npm run dev e abrir localhost:5173.
  2. Conferir que compila: npm run build.
  3. Enviar: git add -A → git commit -m "o que mudou" → git push origin main.
  4. O Cloudflare detecta o envio e publica sozinho, em 2 a 3 minutos.
💻

No PowerShell do Windows, && não funciona para encadear comandos — use ponto e vírgula:
cd C:\Users\User\persontask-app; git push origin main

O que o Cloudflare faz

ConfiguraçãoValor
Build commandnpm run build
Deploy commandnpx wrangler deploy
Node20, lido do arquivo .nvmrc
Variáveis de buildVITE_SUPABASE_URL, VITE_SUPABASE_ANON_KEY
Onde está o sitedist, declarado no wrangler.jsonc
🔁

Reverter uma versão ruim: Cloudflare → Deployments → escolha um deploy anterior → Rollback. Leva segundos e não depende de mexer no código.

🚫

Nunca adicione o arquivo public/_redirects de volta. O Cloudflare o lê e rejeita o deploy com "laço infinito" (código 100324). Quem faz a regra de rota única aqui é o not_found_handling do wrangler.jsonc.

Banco de dados e migrações

Toda mudança de estrutura do banco está em arquivos .sql na pasta supabase/. Todos são idempotentes: rodar duas vezes não quebra nada.

ArquivoO que criou
schema.sqlA base: Espaços, Painéis, Colunas, Itens, membros, permissões, anexos.
crm.sqlOrganizações e pessoas de contato.
schedule.sqlCampos de cronograma no card.
project-schedule.sqlAs tarefas do cronograma dentro do card.
resources-calendar.sqlRecursos com custo/hora e calendário de dias úteis.
done.sqlCard concluído.
reports.sqlMoeda do Espaço e configuração do relatório.
migrate-keep.sqlPadrão ao migrar card entre Espaços.
cron.sqlO agendamento diário do aviso de vencimento.

Como rodar

Supabase → SQL Editor → New query → colar o conteúdo do arquivo → Run.

⚠️

Código novo que depende de coluna nova quebra se o SQL não for rodado antes. Já aconteceu duas vezes: o sininho ficava vazio e o botão Concluir não gravava. Regra: rode o SQL primeiro, publique depois.

Segurança — por que um usuário não vê o Espaço do outro

Não é o código do site que impede: é o próprio banco. Cada tabela tem regras de Row Level Security que só liberam a linha se a pessoa for membro daquele Espaço. Mesmo que alguém chame a API direto, não passa.

Backup

💾

O plano gratuito do Supabase faz backup diário com retenção curta. Se o PERSONTASK virar receita, vale subir de plano por causa do backup, não por causa do tamanho. Enquanto isso, o Table Editor exporta cada tabela em CSV.

E-mails

São dois caminhos diferentes, e confundi-los custa tempo quando algo falha:

CaminhoQuais e-mailsDepende de
Edge Functions → Resend APIAtribuição, menção, vencimento e convite.Segredo RESEND_API_KEY
Supabase Auth → Resend SMTPRecuperar senha, confirmar cadastro.Configuração SMTP no Supabase

Configuração do SMTP

Hostsmtp.resend.com
Porta465
Usuárioresend — tudo minúsculo
Senhaa chave de API do Resend
Remetenteno-reply@persontask.com.br
🔑

O erro que mais custou tempo: escrever Resend com R maiúsculo no usuário do SMTP. A autenticação falha em silêncio e nada aparece nem no log do Resend. Tem que ser resend.

Segredos das funções

Supabase → Edge Functions → Secrets. São três:

  • RESEND_API_KEY — a chave de envio.
  • EMAIL_FROM — PERSONTASK <no-reply@persontask.com.br>
  • APP_URL — https://persontask.com.br, usado nos links dentro dos e-mails.
💣

Rotacionar a chave do Resend quebra os e-mails do app e o sintoma engana: a função responde 200 como se tivesse dado certo. O erro real (401 API key is invalid) só aparece na aba Logs da função — não em Invocations. Se trocar a chave em algum lugar, troque no Secrets também.

🔗

Se o APP_URL ficar vazio, os links dentro dos e-mails apontam para localhost e ninguém consegue abrir. Já aconteceu.

6

Autenticação

Dois jeitos de entrar: e-mail com senha, ou conta Google.

A lista de endereços permitidos

Supabase → Authentication → URL Configuration. O Site URL é o destino padrão; os Redirect URLs são os endereços para onde o login pode devolver a pessoa.

CampoValor atual
Site URLhttps://persontask.com.br
Redirect URLshttps://persontask.com.br/**
https://persontask.netlify.app/**
https://persontask.joabe-reis2.workers.dev/**
http://localhost:5173/**
🎯

Sintoma clássico: você entra pelo Google num endereço novo e o navegador te joga no persontask.com.br. Causa: aquele endereço não está nos Redirect URLs, então o Supabase ignora o destino pedido e manda para o Site URL. Solução: acrescentar o endereço com /** no fim.

Google Cloud Console

🧠

Confusão fácil: o endereço do Supabase (...supabase.co/auth/v1/callback) vai em Authorized redirect URIs. O campo Authorized domains aceita só o seu domínio (persontask.com.br) — pôr o do Supabase ali dá erro.

Trocar de hospedagem não exige mexer no Google: o retorno é sempre para o Supabase, que não mudou.

Domínio e DNS

O domínio está registrado na Locaweb, e o DNS também é lá. Situação atual:

RegistroValorPara quê
@ (A)75.2.60.5Aponta o domínio raiz para o Netlify
www (CNAME)persontask.netlify.appAponta o www para o Netlify
resend._domainkey (TXT)chave DKIMAssinatura dos e-mails
send e rsend (CNAME)*.forge.rmta.netEntrega dos e-mails
_dmarc (TXT)política DMARCReputação do domínio
📧

Os quatro registros de e-mail são sagrados. Perder qualquer um deles faz os e-mails do app irem para spam ou simplesmente não chegarem — e o sintoma demora a aparecer. Antes de mexer em DNS, anote todos.

📭

Não existe registro MX no domínio: a caixa humana é o Gmail contato.persontask@gmail.com. Isso simplifica qualquer mudança de DNS — não há caixa de e-mail para quebrar.

Para mover o domínio para o Cloudflare

O Cloudflare só aceita o domínio raiz (sem www) se o DNS estiver nos servidores dele. Isso exige trocar os nameservers na Locaweb e recriar todos os registros acima. O Cloudflare importa os existentes automaticamente, mas confira um a um depois — principalmente os quatro de e-mail.

Ordem segura: criar tudo no Cloudflare → conferir → só então trocar os nameservers. O Netlify continua servindo enquanto o DNS não vira.

8

Planos: Grátis e Premium

O plano fica na coluna plan da tabela profiles: free ou premium.

Ativar o Premium para alguém

  1. Supabase → Table Editor → tabela profiles.
  2. Procure pelo e-mail da pessoa.
  3. Mude plan para premium e salve.
  4. A pessoa recarrega a página e já tem os recursos.
💳

Não há cobrança automática. A ativação é manual, feita por você. Isso está dito nos Termos de Uso — quando entrar um meio de pagamento, os Termos precisam ser atualizados junto.

O que o Premium libera: vários Espaços, vários Painéis por Espaço, imagem de fundo, fonte, cor de Coluna, logotipo da empresa e Espaços interligados.

Playbook — tarefas comuns

Atualizar o manual do usuário

  1. Editar public/manual.html.
  2. Com o npm run dev rodando, gerar o PDF do próprio HTML:
    msedge --headless --no-pdf-header-footer --print-to-pdf="C:\Users\User\persontask-app\public\PERSONTASK-Manual.pdf" --virtual-time-budget=12000 "http://localhost:5173/manual.html"
  3. Publicar com git push.
📄

O PDF sai do próprio HTML justamente para os dois nunca divergirem. A rota antiga passava por Word e dava retrabalho.

Adicionar um recurso novo ao app

  1. Se mexer no banco, escrever um .sql idempotente em supabase/ e rodar no SQL Editor.
  2. Programar, rodar npm run typecheck e npm run build.
  3. Acrescentar os textos nos três idiomas em src/i18n/locales/.
  4. Testar no local, enviar com git push.

Ver quem está usando

Supabase → Table Editor → profiles mostra todos os cadastros; spaces, quantos Espaços existem.

Apagar a conta de alguém (pedido de LGPD)

Supabase → Authentication → Users → localizar pelo e-mail → excluir. O perfil e os dados associados saem junto, por efeito cascata. A política promete fazer isso em até 30 dias.

Quando quebra

Todos os casos abaixo já aconteceram de verdade. O sintoma vem primeiro, porque é por ele que você chega aqui.

SintomaCausa provávelO que fazer
Nenhum e-mail do app chega, mas a função responde OK Chave do Resend inválida — ela foi rotacionada Supabase → Edge Functions → a função → Logs. Se disser 401, atualizar o segredo RESEND_API_KEY.
E-mail de recuperar senha não chega Usuário do SMTP com maiúscula Supabase → Authentication → Emails → SMTP: usuário tem que ser resend, minúsculo.
Login pelo Google volta para o endereço errado Endereço fora dos Redirect URLs Acrescentar https://SEU-ENDERECO/** em Authentication → URL Configuration.
Deploy falha em "Deploying" com laço infinito O arquivo public/_redirects voltou Apagar o arquivo. A regra de rota é do wrangler.jsonc.
Recurso novo não aparece ou não salva O SQL da migração não foi rodado Rodar o .sql correspondente no SQL Editor.
O site não mostra a versão nova Deploy não passou, ou cache do navegador Conferir Deployments no Cloudflare; depois Ctrl+Shift+R.
Links dentro dos e-mails apontam para localhost Segredo APP_URL vazio Definir APP_URL nos Secrets das Edge Functions.
E-mails caem no spam Reputação de domínio novo, ou registro de DNS perdido Conferir os registros do Resend no DNS. Reputação melhora com o uso.
🔎

Regra geral: antes de mexer no código, veja se o erro é de configuração. Na grande maioria das vezes foi — segredo errado, endereço não liberado ou SQL não rodado.

Custos e limites

ServiçoPlanoO limite que aperta primeiro
CloudflareGrátis500 builds por mês. Na prática, não chega perto.
SupabaseGrátisEspaço em disco e retenção curta de backup. O projeto hiberna se ficar semanas sem uso.
ResendGrátisVolume mensal de e-mails.
LocawebPagoAnuidade do domínio — não deixe vencer.
GitHubGrátisNenhum, para repositório privado deste tamanho.
💸

O Netlify saiu porque o plano gratuito passou a cobrar créditos por deploy e eles acabaram. Fique de olho em mudança de regra dos planos gratuitos — foi exatamente isso que forçou a migração.

📆

Anote a data de renovação do domínio. Domínio vencido tira o app do ar e, dependendo do tempo, pode ser comprado por outra pessoa.

Segredos — onde ficam

🔐

Nada disso entra no GitHub. O arquivo .env está no .gitignore e precisa continuar lá.

SegredoOnde vivePode ser público?
VITE_SUPABASE_ANON_KEYVariáveis do Cloudflare e .env localSim — é feita para o navegador. Quem protege os dados é o RLS.
service_role do SupabaseSó no painel do SupabaseNÃO. Ignora todas as regras de segurança.
RESEND_API_KEYSecrets das Edge Functions e SMTP do AuthNÃO.
Client Secret do GoogleGoogle Cloud Console e SupabaseNÃO.
Senhas de Cloudflare, Supabase, LocawebGerenciador de senhasNÃO.
🧯

Se vazar alguma chave: gere uma nova no painel do serviço e atualize todos os lugares que a usam. No caso do Resend são dois — o Secrets das funções e o SMTP do Auth. Esquecer um deles quebra metade dos e-mails em silêncio.
